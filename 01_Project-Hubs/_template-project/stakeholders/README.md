# stakeholders/

**TL;DR:** One-page profiles of the cross-functional partners on this project — who cares about what, what they own, and how they plug into the loop.

Not RACI. Not an org chart. A working reference.

## Why this folder exists

When a new XFN joins mid-project, or when a decision needs a specific reviewer, this folder answers: *who do I talk to, what do they care about, and what do they own?* — in one page per function.

## What belongs here

One file per XFN function, kebab-case:

- `product.md` — Product Manager(s)
- `engineering.md` — Engineering lead(s)
- `marketing.md` — Marketing / GTM
- `sales.md` — Sales / customer-facing
- `legal-privacy.md` — Legal, privacy, security, compliance
- `research-participants.md` — End users we recruit (structure only, never names)
- `sponsor.md` — Exec sponsor(s)
- `support.md` — Customer support / success, if relevant
- `finance.md` — Finance / procurement, if relevant

Only create the files for functions actually on this project. Don't make empty ones.

## File structure

Each file is short — one page. It answers:

1. **Who** (name, role, timezone, preferred channel)
2. **What they care about** (in their words, not yours)
3. **What they own** (decisions, sign-offs, Traffic Lights that involve them)
4. **When they plug in** (which phase, which workflow step)
5. **How we'll communicate** (status update? direct message? named review?)

## Template

Start from §C (stakeholder map) of the hub's `intake.md`, copied from [`0-1-Intake_initiative.template.md`](../../../00_README/_templates/0-1-Intake_initiative.template.md). For a detailed profile, expand a row from §C1 into a standalone file with the structure above. Wiki stakeholder entities (`_wiki/entities/`) hold their sourced positions; these profiles link to them rather than repeat them.

## Conventions

- First-person voice from *your* side — "I'll send her the status note after each review" — not legalese.
- If a function has multiple people, list them as a table in the same file.
- Keep it current. A stale stakeholder file is worse than none.
- Profiles describe roles and working preferences, not private details. In a customer hub they are customer content ([CONVENTIONS §4](../../../00_README/CONVENTIONS.md#4-customer-data-labels)).
