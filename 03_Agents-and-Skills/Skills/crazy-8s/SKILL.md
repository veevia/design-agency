# Crazy 8s

**TL;DR:** A rapid-fire sketching exercise: fold a piece of paper into 8 panels, set a timer for 8 minutes, and sketch 8 different ideas — one per panel. The constraint (8 ideas, 1 minute each) forces quantity over quality, which is exactly the point. The best ideas rarely come first; Crazy 8s makes you get past the obvious ones fast.

## When to use

- After Mind Mapping and Lightning Demos, before Solution Sketch
- When the team keeps converging on the same two ideas
- When you need to explore a range of approaches before committing

## Materials

- A4/letter paper folded into 8 panels (fold in half 3 times)
- Permanent marker or thick felt-tip pen (forces sketching at the right level of abstraction — no micro-detail)
- Timer set to 8 minutes

## The constraint rules

- **8 panels, 8 minutes.** One idea per panel. When the timer goes, pencils down.
- **Silent.** No talking, no showing, no explaining to neighbours.
- **No words only.** Every panel must have a sketch — even a rough rectangle with labels counts. Word-only panels are not sketches.
- **Different ideas.** Panel 2 should not be "Panel 1 but slightly modified." Push for genuine variation.
- **No polish.** Thick marker, rough shapes, labels. Stick figures are fine.

## Steps

1. **Set up (2 min):** Distribute paper. Everyone folds into 8 panels. Set up visible countdown timer.
2. **Explain the rules (1 min):** "8 different ideas, 1 minute each. Silent. Different — not variations of the same thing. When the timer goes, you must stop."
3. **Sketch round (8 min):** Silent. Facilitator calls out each minute: "Minute 1 done — move to panel 2."
4. **Self-review (2 min):** Each person reviews their own sketches silently. Circle their 1–2 favourite panels.
5. **Optional share-out:** Post on the wall. Each person explains their top 2 panels in 90 seconds. No critique.
6. **Into Solution Sketch:** The best panel (or combination of panels) becomes the basis for the detailed Solution Sketch.

## What to sketch

If the sprint target is "the Lead Coordinator checking a request," possible Crazy 8s variations:

| Panel | Concept variation |
|---|---|
| 1 | Urgency meter — shows the AI urgency score next to each request |
| 2 | Side-by-side comparison — the request vs. the most similar past confirmed request |
| 3 | "Assign to specialist" button — instant one-tap assignment with the specialist pre-selected |
| 4 | Booking checklist — structured 3-step checklist (customer, service contract, parts) |
| 5 | Colour-coded status — Unconfirmed (grey) / Checking (amber) / Confirmed (green) inline in queue |
| 6 | Record cards — each request shows its 3 key records (CRM, service contract, inventory system) inline |
| 7 | Shared checking — multi-coordinator "confirmed by" with initials shown |
| 8 | Request history — shows this type of request's track record: how many were urgent, which parts were needed |

## Techniques for generating variation

When stuck on panels 5–8:

| Technique | How to apply |
|---|---|
| **Reverse** | What if the user checked nothing and the system did it all? |
| **Steal from demo** | Which lightning demo big idea haven't I tried yet? |
| **Different actor** | How would this look if it were designed for a 60-year-old non-tech site supervisor? |
| **Remove a step** | What if checking was eliminated entirely (trust level shown instead)? |
| **Worst possible** | Sketch the worst possible UI. Often reveals by inversion what the best should do. |
| **Escalate** | What happens when this request is an emergency (a safety risk)? Design that variant. |

## Output

8 hand-sketched panels per person. Top 1–2 per person feed into [Solution Sketch](../solution-sketch/SKILL.md).

## Agent facilitation guide

When generating Crazy 8s concepts as an agent (for async sprints or solo design leads):
1. State the sprint target moment clearly
2. Generate 8 distinct concept directions — each fundamentally different in approach (not just visual variation)
3. Label each with: concept name + one-line description + key interaction mechanism
4. Self-evaluate: circle the top 2 (most different from each other + most directly addressing the Sprint Questions)
5. Carry those 2 into Solution Sketch development

```markdown
## Crazy 8s — Agent Output — [Sprint Name]

**Sprint target:** [user] + [target moment]

| Panel | Concept name | Key mechanism | Addresses Sprint Q |
|---|---|---|---|
| 1 | Urgency meter | Numeric score + colour = request urgency at a glance | Q2 (can users tell confirmed vs. not?) |
| 2 | Reasons card | Inline records for every request without leaving the queue | Q2 |
| 3 | Checking flow | Step-by-step: customer → service contract → parts → confirm | Q2 + Q5 |
| ... | | | |

**Top 2 for Solution Sketch:** Panel 1 (urgency meter) + Panel 3 (checking flow)
```

## Watch-outs

- **Everyone draws the same idea:** Happens when someone shows their sketch before others finish. Keep it silent until all 8 panels are done.
- **"I'm not a good sketcher":** Doesn't matter. Crude rectangles with labels are fine. The idea is the output, not the art.
- **Giving up at panel 5:** The constraint is the point. Panels 6–8 are often the most interesting because they're the least obvious.
- **Skipping this and going straight to Solution Sketch:** Teams that skip Crazy 8s consistently produce less diverse solution sketches. The 8-minute investment is always worth it.
